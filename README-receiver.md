# До пяти аккаунтов-получателей чеков

## Вход и настройка прямо в боте

Открой `/start` → «Аккаунты-получатели (до 5)» → «Получатель №1: войти / заменить».
Затем повтори вход для слотов №2, №3, №4 и №5 с разными аккаунтами.
В меню показано, какие слоты настроены, и Telegram ID каждого получателя.
Достаточно от одного до пяти получателей; пустые слоты пропускаются.
Существующий получатель автоматически остаётся в слоте №1.
В личном чате своего бота введи номер, код Telegram и пароль 2FA, если нужен.
Функция доступна только числовому ADMIN_ID. При настройке воркер останавливается;
после успешного входа запусти его снова через главное меню. Перезапуск службы
для применения этой настройки не требуется.

Номер, код и пароль бот старается удалить из чата после обработки. При отмене,
переходе в меню, завершении приложения или истечении 5 минут временный клиент
отключается. Предыдущая сессия получателя заменяется только после успешного входа.
Telegram может отклонить код или завершить его срок действия — новый код нужно
запрашивать заново; бот не обходит ограничения Telegram.

Кнопка «Проверить подключение» проверяет авторизацию всех настроенных получателей и доступность
выбранного бота, не открывая чек. Если бот выдаёт ссылки другого бота, укажи
точный @username из ссылки через «Бот из ссылки чека». Например, если ссылка
начинается с `https://t.me/send?start=`, выбери `@send`, даже когда чек выдал
`@OnoGo_bot`. По умолчанию выбран `@OnoGo_bot`.

Настройки `check_receiver_enabled`, `check_receiver_account_id` (слот №1),
`check_receiver_account_id_2` … `check_receiver_account_id_5` и
`check_receiver_bot` сохраняются в SQLite. Настройка включения из меню имеет
приоритет над старым `CHECK_RECEIVER_ENABLED` в `.env`.

## Альтернативный вход через терминал

На VPS останови бота и войди в свой аккаунт-получатель:

```bash
cd /root/Whhwha
sudo systemctl stop whhwha
.venv/bin/python login_receiver.py
sudo systemctl start whhwha
```

Скрипт запросит номер, код Telegram и пароль 2FA (если установлен).
Код и пароль вводятся скрыто в терминале VPS. Не отправляй их в чат бота.
После подтверждения `YES` в `.env` включается `CHECK_RECEIVER_ENABLED=1`.
Для отключения установи `CHECK_RECEIVER_ENABLED=0` и перезапусти службу.

Авторизации хранятся отдельно: `receiver/recipient.session` для №1,
`receiver/recipient_2.session` … `receiver/recipient_5.session` для №2–№5.
Скрипт входа через терминал настраивает только слот №1; остальные добавляются
через меню бота. Получатели не добавляются
в рабочую очередь. Папка `receiver/` исключена из Git; не передавай её другим.
Не запускай скрипт входа, пока служба использует эту сессию.

После сохранения нового чека бот последовательно открывает ссылки выбранного
бота через Telegram StartBotRequest. Чеки распределяются по кругу между
настроенными получателями: 1 → 2 → 3 → 4 → 5 → 1. Один чек получает один аккаунт;
на остальные аккаунты тот же чек автоматически не отправляется. Назначение,
позиция очереди и общий срок ожидания сохраняются в `receiver/opened.sqlite3`.
После отмены или перезапуска назначенный чек остаётся за тем же аккаунтом.
Если этот аккаунт заменён, чек требует ручной проверки. Повторяющиеся аккаунты
в разных слотах не допускаются. Если один настроенный получатель не авторизован,
воркер останавливается до исправления его входа. Ссылки других ботов
автоматически не открываются.
После отправки запроса получатель до 8 секунд ожидает ответ выбранного бота.
Статусы: «Чек активирован», «Чек уже активирован ранее», «Чек не активирован»
или «Активация не подтверждена». Результат сохраняется в SQLite и виден
в уведомлении администратору и разделе «Чеки», включая после перезапуска.
Старые чеки и чеки при выключенном получателе отмечены как непроверенные.

Точный свежий ответ «Вы получили 0.1$.» (с любой числовой суммой)
в последовательном диалоге с выбранным ботом считается подтверждением.
Для других формулировок требуется распознанный явный ответ со ссылкой на
start-параметр этого чека либо ответ на отправленную команду /start.
Несвязанные сообщения, меню, баланс, неизвестный текст и таймаут не считаются
успешной активацией; короткий ответ бота показывается для ручной проверки.
Форматы ответов разных ботов могут отличаться — неизвестные формулировки
дают статус «Активация не подтверждена». Повторной активации ради проверки нет.

Журнал `receiver/opened.sqlite3` предотвращает повторные открытия одного
start-параметра для одного бота, включая перезапуски. При обрыве соединения результат может
остаться неизвестным; такие чеки нужно проверять вручную, автоматического
повтора нет. Ошибка открытия не удаляет сохранённый чек.

По умолчанию аккаунты входят и обрабатываются по очереди: следующий запускается
после завершения предыдущего. Это применяется и к существующим установкам.
Добавить можно 5–10 и больше аккаунтов. В «Настройки» кнопка «Аккаунты»
переключает последовательную обработку / 5 параллельно / 10 параллельно.
Изменение применяется при следующем запуске воркера. Аккаунты добавляются
через «Добавить по номеру», отправкой файлов `.session` или сканированием папки;
можно добавить больше десяти — одновременно обрабатывается только выбранное число.
Получатели открывают чеки по очереди с общим интервалом минимум 10 секунд
между запросами, включая переход к другому аккаунту. При FloodWait вся очередь
ждёт указанный Telegram срок плюс секунду и повторяет отклонённый запрос
тем же аккаунтом. Смена аккаунта не сокращает ожидание. Интервал снижает частоту запросов, но не гарантирует
отсутствия FloodWait. Неопределённый результат при обрыве связи не повторяется.
Счётчик «Отправлено 10/20/30 чеков» считает успешные
отправки сообщений администратору за текущий запуск, а не зачисления.
