# Объединённая панель Jdjdj + Session + Whhwha

Добавлена одна точка входа (python -m unified.main), один Telegram-токен,
одно меню и адаптеры просмотра статистики из трёх проектов.

**Важно:** это первый, безопасный этап объединения, а не полная
функциональная замена старых ботов. Автоматический сбор файлов .session/tdata,
извлечение кодов входа, массовая миграция и очистка аккаунтов, а также
автоматизация сторонних финансовых ботов не подключены. Исходные точки
запуска не изменены.

## Запуск

1. Используйте Python 3.10+.
2. Установите: pip install -r requirements.unified.txt
3. Перенесите настройки из .env.unified.example в приватный .env.
4. Укажите новый UNIFIED_BOT_TOKEN и свой числовой UNIFIED_ADMIN_IDS.
5. При необходимости задайте JD_STORAGE_DIR, SESSION_DB_PATH и WHHWHA_DB_PATH.
6. Запустите: python -m unified.main
7. В Telegram напишите /start или /status.

Не запускайте несколько polling-процессов с одним токеном.
Пути к базам и каталогам должны указывать на локальные файлы, доступные
программе. Все запросы к SQLite выполняются только для чтения.

## Реализовано

- Ограничение доступа по числовым ID (если список пуст, запуск запрещён).
- Одна панель, три раздела, сводка, команды /start, /menu, /status, /help.
- Только агрегированные счётчики; не читаются коды, телефоны и ключи.
- Файлы, присланные в чат, не скачиваются.
- Тесты: python -m unittest discover -s tests -p test_unified_metrics.py

## Срочные меры защиты

В истории репозитория Session присутствуют .env и Telegram .session,
в Whhwha — .env. Если данные действующие, считайте их скомпрометированными:
отзовите соответствующие Telegram-сессии и смените токены и API-секреты.
Добавление .gitignore не удаляет уже сохранённые файлы из истории Git.
Этот PR не копирует секреты и не меняет историю исходных репозиториев.
