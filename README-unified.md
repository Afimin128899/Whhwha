# Единый Telegram-бот — безопасная интеграция

Это **отдельная точка входа** в репозитории `Whhwha`: один токен, один процесс polling, одна панель администратора для трёх источников (`Jdjdj`, `Session`, `Whhwha`). Исходные приложения и их файлы не изменены.

## Что реализовано

- `/start`, `/help` — единое меню; доступ строго по числовому `ADMIN_ID` (никакой проверки по username).
- `/audit`, `/status` — **только чтение**: количество локальных файлов из Jdjdj и агрегированная статистика статусов в SQLite проектах Session/Whhwha.
- `/sources` — подключённые источники.
- Если прислать ZIP от администратора: показать число `.session`, `.json` и записей `tdata` **по именам** (содержимое не извлекается, Telegram-сессии не открываются, архив не сохраняется); лимиты 20 МиБ и 2000 элементов.

**Это частичное безопасное объединение**: операции чтения кодов из Telegram-сессий, захвата/миграции аккаунтов, массовой очистки и автоматического создания финансовых чеков намеренно не перенесены в общий исполняемый процесс.

## Запуск

```bash
python -m pip install -r requirements-unified.txt
# На сервере: создайте .env из .env.unified.example и укажите новые BOT_TOKEN и ADMIN_ID
python run_unified.py
```

Укажите абсолютные локальные пути через `UNIFIED_JDJDJ_DIR`, `UNIFIED_SESSION_DB` и `UNIFIED_WHHWHA_DB`. Необязательные отсутствующие источники показываются как «не подключён». Значение `UNIFIED_WHHWHA_DB` по умолчанию — `bot_database.sqlite3` в корне текущего репозитория.

**Важно:** не запускайте `main.py`/`bot.py` старых проектов с тем же `BOT_TOKEN` параллельно: они будут конфликтовать за polling обновлений. Для одного Telegram-бота запускайте **только** `run_unified.py`.

## Защита секретов

В исходных репозиториях были закоммичены `.env`, файлы авторизации `.session` и ключи прямо в Python-коде. Рассматривайте такие значения как скомпрометированные. Смените токены ботов и API-ключи, прекратите использовать старые авторизации, удалите чувствительные файлы из актуальных коммитов и при необходимости очистите историю Git с учётом резервных копий. Нельзя полагаться на `.gitignore`, если файлы уже отслеживаются Git.

Этот бот не принимает `.session` как отдельные файлы, не читает их содержимое и не взаимодействует с пользовательскими Telegram-аккаунтами. Он не создаёт и не удаляет данные в SQLite источников.
